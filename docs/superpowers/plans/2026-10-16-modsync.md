# modsync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A small cross-platform native app (Zig + OS webview) that keeps one Minecraft install's `mods/` folder in sync with the newest release jars from a configurable set of GitHub repos.

**Architecture:** A single Zig binary embeds an HTML/JS UI and shows it in the OS's native webview (WKWebView on macOS). App logic (config, GitHub API, install) lives in Zig modules behind a thin JS→Zig bridge; the UI pushes state back via `webview_eval`. Network uses Zig stdlib only; releases are fetched from the GitHub REST API and the `.jar` asset is dropped into `mods/`, replacing the previously-installed jar for that repo.

**Tech Stack:** Zig (Homebrew), webview/webview C library (vendored), `std.http.Client`, `std.json`, HTML/CSS/vanilla JS.

**Spec:** `docs/superpowers/specs/2026-10-16-modsync-design.md`

## Global Constraints

- Zig toolchain via Homebrew (`brew install zig`); record the exact `zig version` in Task 1 and target that version's `std.http` API.
- Networking: Zig standard library only (`std.http.Client`, `std.json`). No vendored curl or C HTTP stack. If std TLS is unworkable, surface it — do not silently vendor a dependency.
- Release selection: list releases (newest-first), take the **first non-draft** release. Prereleases ARE included by default (foley/earshot/yakvc publish only prereleases).
- Jar asset selection rule (deterministic):
  1. Filter assets to names ending `.jar` AND not containing `cli` AND not containing `server`.
  2. Of those, prefer names starting with `{repo}-` (e.g. `gore-`).
  3. If still multiple, take the largest by byte size.
  4. Zero qualifying jars → that row errors; refresh continues for other repos.
- Install replace rule: when installing repo `X`, delete any `mods/X-*.jar` that is not the jar being installed (prefix match). Never touch any other file in `mods/`.
- Seeded tracked repos (default config): `cumsauce/gore`, `cumsauce/foley`, `cumsauce/earshot`, `cumsauce/stalker`, `desocketed/yakvc`.
- Config path: macOS `~/Library/Application Support/modsync/config.json`; Linux `~/.config/modsync/config.json`; Windows `%APPDATA%\modsync\config.json`.
- v1 acceptance = macOS binary builds and runs. Code keeps no platform-forked logic beyond path handling and webview bootstrap.
- Binary name: `modsync`, output at `zig-out/bin/modsync`.

## Review Focus

These are the failure modes the spec implies but that no single task's happy-path test exercises; each is pinned to a task below.

- **Prerelease-only repos (foley/earshot/yakvc):** a naive `/releases/latest` call returns 404 for them. Expect: the list endpoint + first-non-draft rule yields their newest prerelease. → pinned in Task 3 tests.
- **yakvc multi-asset releases:** must pick the single client `.jar`, not the prism zip / mrpack / CLI / server / SHA256SUMS assets. → pinned in Task 3 tests.
- **First-run hand-downloaded jars:** user's `mods/` already has `gore-0.1.1.jar` etc. installed by hand. Expect: installing `gore-0.1.2.jar` removes the old `gore-0.1.1.jar` (prefix match) so no duplicate-mod launch failure. → pinned in Task 4 tests.
- **Repo with no releases (the future "surprise mod"):** expect a clean per-row "no releases" status, refresh does not abort other rows. → pinned in Task 6 tests.
- **Download URL redirects:** `browser_download_url` redirects to a CDN. Expect: redirects are followed so the jar body is fully captured. → pinned in Task 5 verification.

### Task 5: Network layer (fetch releases + download jar)

**Files:**
- Create: `src/net.zig`

**Interfaces:**
- Consumes: `parseReleases`, `selectRelease`, `selectJarAsset` from Task 3.
- Produces:
  - `pub const FetchedMod = struct { tag: []const u8, jarName: []const u8, jarSize: u64 };`
  - `pub const FetchError = error{ NoReleases, NoJarAsset, Http, ... } || std.mem.Allocator.Error;`
  - `pub fn fetchLatest(allocator, client: *std.http.Client, owner: []const u8, repo: []const u8, token: ?[]const u8) FetchError!?FetchedMod` (null / error on no-releases; returns tag + selected asset metadata, does NOT download)
  - `pub fn downloadJar(allocator, client: *std.http.Client, url: []const u8, destTmpPath: []const u8, token: ?[]const u8) !void` (follows redirects; writes body to `destTmpPath`)
- Tests inline are limited to JSON/selection (already covered in Task 3); network calls verified manually in Step 2.

- [ ] **Step 1: Implement `src/net.zig`**

`fetchLatest`: GET `https://api.github.com/repos/{owner}/{repo}/releases?per_page=100` with headers `User-Agent: modsync` and, if token present, `Authorization: Bearer {token}`. Parse body with `parseReleases`; `selectRelease`; if null return `error.NoReleases`; `selectJarAsset`; if null return `error.NoJarAsset`; return `FetchedMod{tag, jarName, jarSize}`.
`downloadJar`: GET `url` with `User-Agent` (+token if given); configure the request to follow redirects (`max_redirects`); stream response body to `destTmpPath`.
